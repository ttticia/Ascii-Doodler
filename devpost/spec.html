Implementation blueprint / 03

Doodle to ASCII

A local, responsive browser app: draw, convert the marks into a compact `#` image, and download it as text.

How this works

The browser does the work

The page is made of HTML, CSS, and JavaScript. The browser provides a square drawing surface called a canvas. It holds the user's marks only while the page is open.

When the user submits, JavaScript checks the drawing, turns it into a grid of `#` marks and spaces, and shows the result. The browser packages that text into a `.txt` download. Python serves the page locally; it does not process the drawing.

Data flow / no external service

From pointer to text file

Python serves files → browser canvas records marks → JavaScript converts a 50 × 50 grid → browser previews and initiates `.txt` download. Drawing data never leaves the page.

The local server sends files; the browser handles the drawing, conversion, and download.

Components mapped to the PRD

What each piece owns

No framework
Editor canvas and tools / `src/drawing.js`

Keep a 500 × 500 logical canvas that scales visually to the responsive layout. With 50 analysis columns, each cell is 10 logical pixels wide. The black pen is 3 pixels wide (30% of a cell); the white eraser is 9 pixels wide (90%). Pointer events handle mouse, touch, and stylus input. No tool is selected until the user clicks the pen or eraser.

Check the actual current pixels when submitting, so a doodle erased completely is treated as blank. The welcome message prevents drawing until dismissed. Tool buttons stay above the square canvas, with Submit below it.

PRD ref: `Welcome and Editor` / `Screens and Layout`

ASCII conversion / `src/ascii.js`

Read the canvas pixels into a 50 × 50 analysis grid. For each cell, measure black-mark coverage; partial antialiased pixels count according to their darkness. Since Canvas channels are 8-bit, subtract half a shade step (`0.5 / 255`) before comparing. Write `#` only when adjusted coverage is above 15%; an exact 15% cell remains blank. A straight pen stroke 30% of a cell wide qualifies. Crop empty rows and columns without distorting the remaining character grid.

The text contains `#`, spaces, and line breaks only, with every line no longer than 50 characters. Conversion is deterministic and local; it produces one result.

PRD ref: `Submit and Generate` / `The Core Journey`

Screen flow and download / `src/app.js`

Track the current view, welcome-message visibility, active tool, and generated string in memory. On submit, reject blank input; otherwise show “Generating art :)”, allow the browser to paint that view, then convert. If conversion fails, return to the editor with the drawing intact and show “could not generate art. please try again”.

The result view uses a monospace preview. At wider widths, the message box sits left of the art with Download below; at phone widths, stack the message before the art.

For download, create a text Blob and temporary object URL, activate a link named `ascii-doodle.txt`, then release the URL. Show “image downloaded” when the app initiates it. If preparing or initiating the file throws a detectable error, show “download failed. please try again”. The page cannot know if the browser later blocks or cancels the save.

PRD ref: `The Core Journey` / `Result and Download` / `States and Boundaries`

Data and what resets

The canvas is the drawing source. Tool selection, page view, and result text are also kept only in the open page. Refreshing or closing the tab clears everything; there is no save or restore behavior in this proof of concept.

PRD ref: `The Core Journey` / `The POC Boundary`

Local demo / no install

Run it on this computer

From the project root, start Python's built-in file server:

python -m http.server 8000

Then open http://localhost:8000/. Stop the server with Ctrl+C.

What to verify during build

Observable checks

Editor and conversion

  • At phone and desktop widths, the canvas remains square and controls stay outside it.
  • The welcome message blocks drawing; drawing starts only after selecting the pen.
  • A line crossing a cell qualifies at the 15% rule; a cell at or below 15% remains blank.
  • Erasing every mark makes **Submit** show “canvas cannot be blank”.

Result and take-away

  • Generated art uses `#` and spaces only, preserves the shape, trims empty margins, and stays within 50 characters per line.
  • Generation errors return to the editor with the doodle preserved and the retry message visible.
  • The `.txt` contains the same characters and line breaks as the preview.
  • App-side download errors show the error pop-up; browser cancellation is not reported as confirmed failure.

Boundary and references

What stays out

No framework, backend, login, storage, image import, JPG/PNG export, extra tools, adjustable color palette, multiple output versions, or clipboard copy. The app is local and self-contained to protect the short proof-of-concept path.
